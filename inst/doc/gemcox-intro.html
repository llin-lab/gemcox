Introduction to gemcox

GeM-Cox looks for latent subgroups of subjects whose survival mechanisms differ: the same immune markers relate to the hazard differently in different people. It combines a Gaussian mixture for clustering features with a separate Cox model in each subgroup, all sharing one baseline hazard, so subgroups differ only in their coefficient vectors. This vignette fits the model to one simulated dataset, looks at what it estimates, and tests whether two subgroups are needed.

library(gemcox)

Simulated data

gemcox_simulate() generates two equally likely latent clusters. Their feature profiles are mu_sep apart and their Cox coefficient vectors are beta_sep apart; the two coefficient vectors have equal length, so a different mechanism is never confounded with a stronger effect. Here the profiles overlap substantially (mu_sep = 0.5) and the mechanisms differ clearly (beta_sep = 2).

d <- gemcox_simulate(n = 400, p = 6, mu_sep = 0.5, beta_sep = 2, seed = 42)
dim(d$X)
#> [1] 400   6
mean(d$status)          # proportion of subjects with an event
#> [1] 0.535

Fitting the model

The defaults are the settings validated in the package simulations: K = 2, gamma = 1, a small ridge penalty (lambda = 0.05, alpha = 0), a shared baseline, diagonal covariance, and k-means initialisation.

fit <- gemcox(d$X, time = d$time, status = d$status, K = 2)

Membership weights

Each subject gets a weight tau for each cluster rather than a hard label. Here the weights are soft: most subjects are not confidently assigned.

head(round(fit$tau, 3))
#>         C1    C2
#> [1,] 0.003 0.997
#> [2,] 0.116 0.884
#> [3,] 0.273 0.727
#> [4,] 0.112 0.888
#> [5,] 0.614 0.386
#> [6,] 0.626 0.374
hist(apply(fit$tau, 1, max), breaks = 20, xlim = c(0.5, 1),
     main = "Largest membership weight per subject", xlab = "max tau")

This is expected. When subgroups differ mainly in mechanism, a single subject’s data carries little evidence about which subgroup they belong to, and that evidence does not grow with the sample size. Individual labels are therefore not the target of estimation; the difference between the subgroups’ coefficient vectors is.

Is a second subgroup needed?

gemcox_heterogeneity_test() tests K = 2 against K = 1, where the null hypothesis is one mechanism with a shared coefficient vector. Its default statistic is the likelihood ratio of the two fits, and its null distribution comes from a parametric bootstrap under the fitted K = 1 model: event times are resimulated from that model, censoring from its Kaplan-Meier estimate, and both models are refitted each time.

The likelihood ratio requires gamma = 1 (the default). For speed this example uses only B = 19 bootstrap replicates, which is enough to show the call but gives a coarse p-value; use at least 200 in practice.

ht <- gemcox_heterogeneity_test(fit, B = 19, seed = 1)
#> Warning: 1 of the fits (observed and null data) stopped at max_iter without
#> converging.
ht
#> 
#>  GeM-Cox test of K = 2 vs K = 1: parametric bootstrap null, in-sample
#>  likelihood ratio
#> 
#> data:  400 subjects, 214 events
#> LRT 2(l2 - l1) = 44.853, valid null replicates = 19, p-value = 0.05

In the package simulations (n = 400-800, p = 10), this test: - rejected at close to the nominal 5% under the null; - had 30-57% power when the mechanisms differed by beta_sep = 2.

Those simulations used the earlier EM setting (tol = 1e-4, max_iter = 100). Calibration at the current default (tol = 1e-8, max_iter = 1000) has not yet been established, so treat these figures as provisional. Power is modest with few events, so a non-significant result is inconclusive: it does not show that the mechanisms are the same.

What gamma does

When GeM-Cox decides how strongly a subject belongs to each subgroup, it combines two kinds of evidence: how the subject’s markers compare with each subgroup’s typical profile, and how well each subgroup’s survival model explains what actually happened to the subject. gamma sets how much the second kind of evidence counts.

  • gamma = 0 uses the markers only. Subgroups that differ in mechanism but not in marker profile are then invisible, however large the data.
  • gamma = 1 (the default) weights the outcome exactly as the joint probability model does. This is what lets the mechanism difference be recovered.
  • Larger values make the outcome dominate and can create subgroups that are not there.

gamma is fixed at 1 rather than tuned: in simulation, data-driven choices either pushed it to 0, losing the signal, or inflated false discoveries.

Predicting for new subjects

A new subject’s outcome is unknown, so their membership weights come from their markers alone.

new <- gemcox_simulate(n = 3, p = 6, mu_sep = 0.5, beta_sep = 2, seed = 7)
predict(fit, new$X, type = "tau")
#>             C1        C2
#> [1,] 0.3534247 0.6465753
#> [2,] 0.7955691 0.2044309
#> [3,] 0.1682633 0.8317367
predict(fit, new$X, type = "survival", times = c(50, 150, 300))
#>           t=50     t=150      t=300
#> [1,] 0.8970739 0.6366223 0.40164588
#> [2,] 0.9010644 0.6476150 0.41418448
#> [3,] 0.6805446 0.2222889 0.06764889

When to use GeM-Cox

GeM-Cox is most useful when marker profiles overlap between subgroups but are not identical, and survival mechanisms differ. Its advantage over a single Cox model or a cluster-then-fit approach grows with the number of events and shrinks as the number of features grows relative to the events. Two subgroups (K = 2) is the validated setting.
